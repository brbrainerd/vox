# Semantic Behavior Map — `vox-plugin-test-harness`

All 6 extracted claims live in `crates/vox-plugin-test-harness/src/lib.rs` and originate from 3 tests (`code_builder_roundtrip`, `skill_builder_roundtrip`, `plugin_dir_touch`). After dedup, they cover 5 symbols. Every single claim is `kind: happy` — the crate has **no proven error path, no edge case, and no invariant** anywhere in this claim set. The surfaces exercised are precisely the kind that carry failure contracts (a TOML parser, a manifest validator, and a filesystem mutator), so the happy-only coverage is a meaningful semantic hole rather than acceptable for trivial accessors.

## Plugin
- **Proven (happy):** A `Plugin` populated via a `CodeManifestBuilder` round-trip has `id` and `name` fields equal to the builder inputs.
- **Error path:** none.
- **Edge/invariant:** none (no empty/duplicate/invalid id or name).

## SkillManifestBuilder
- **Proven (happy):** Produces a manifest whose `plugin.id` equals the builder's input id.
- **Error path:** none.
- **Edge/invariant:** none.

## PluginDir::from_toml
- **Proven (happy):** Succeeds on valid TOML produced by `CodeManifestBuilder` (asserted twice — `code_builder_roundtrip` and `plugin_dir_touch`; deduped to one distinct behavior).
- **Error path:** none — never fed malformed, invalid, or missing-field TOML.
- **Edge/invariant:** none. The valid input is generated by the same builder family, making the round-trip partly self-fulfilling.

## PluginDir::parse_manifest
- **Proven (happy):** Completes a round-trip without error on a valid manifest.
- **Error path:** none — no rejection of invalid/incomplete/conflicting manifests.
- **Edge/invariant:** none.

## PluginDir::touch
- **Proven (happy):** Creates a file at a path relative to the plugin directory.
- **Error path:** none — no proof of behavior for missing parent dir, pre-existing file, or unwritable/invalid path.
- **Edge/invariant:** none.

## Semantic gaps

These symbols are proven **only** on the happy path yet clearly own a failure/empty/conflict contract:

1. **`PluginDir::from_toml` (validator with no rejection test).** It is the crate's TOML ingestion boundary, but is only ever handed valid TOML emitted by `CodeManifestBuilder`. There is no proof it *rejects* malformed syntax, an invalid schema, or missing required fields. Because input and parser share a builder lineage, the round-trip is self-fulfilling — the most actionable gap. **Add a negative test: garbage/invalid TOML must return an error.**

2. **`PluginDir::parse_manifest` (validator with no rejection test).** Proven only to complete on a valid manifest. No proof it surfaces an error on an invalid, incomplete, or internally-conflicting manifest. **Add a malformed-manifest rejection test.**

3. **`PluginDir::touch` (mutator with no failure path).** Filesystem mutation proven only on the clean create case. Unproven: missing parent directory, collision with an existing file, and unwritable/invalid path. **Add at least the missing-parent and existing-file cases.**

4. **`Plugin` / `SkillManifestBuilder` (round-trip-only invariants).** Field equality is asserted but no edge behavior — empty id, duplicate/whitespace name, invalid characters — is exercised. Lower priority than the validators/mutators above, but still happy-only.
