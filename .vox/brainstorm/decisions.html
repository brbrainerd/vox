Sub-Spec 1 — Placement: perf-native vs GUI as a language property

Every declaration gets one placement, inferred from the effect/capability system you already have, overridable with @place(...).

native
Rust + interp. db, fs, net, spawn, @server/@query/@mutation, @table, @scheduled, actor, workflow.
shared
Emits to both. @pure logic, types/ADTs, validation, formatting — no tier-specific calls.
gui
TypeScript. component, @reactive, JSX, DOM/browser-only state.

A GUI→native direct call is rejected with a fix-it: “wrap in @query fn.” Crossing the boundary must go through the existing RPC decorators — so the client/server split stops being convention and becomes a compiler-checked contract. Placement is literally feature_matrix’s per-feature FRONTEND/BACKEND-ONLY, lifted to the per-declaration level and computed automatically.
