## Starting premise: separate cancelled from failed

Classifying the last 30 runs of all 47 workflows, and **distinguishing cancelled from failed** — the distinction a first pass missed:

| Class | Count | Remedy |
|---|---|---|
| **ALL CANCELLED** | 8 | Make *faster*. Not broken — slower than the commit cadence, so every run is superseded. |
| **BROKEN** | 13 | Fix or delete. |
| **FLAKY** | 3 | Investigate. |
| **NEVER RUN** | 2 | Delete or wire up. |
| Healthy | ~21 | Leave alone. |

**26 of 47 produce no reliable signal.** ALL CANCELLED: `ci.yml`(28), `compile-matrix`(28), `cr-l-gates`(28), `gui-cross-build`(28), `cr-l8-corpus-feedback`(27), `docs-quality`(27), `mobile-eas-build`, `mobile-e2e-android`.

**Rule — apply it to every judgement in this plan:** never judge a workflow by raw success rate. 0/30-because-always-cancelled and 0/30-because-always-fails need opposite remedies and the raw number cannot tell them apart. Applying it to `cross-platform-check`: 6 success / 1 failure / 22 cancelled = 86% excluding supersessions, i.e. genuinely healthy.

Hosted runners are **free** for public repos (measured: `"billable":{"UBUNTU":{"total_ms":0}}`). Latency, not cost, is the constraint.

## Task 5: Nightly lane and a dated prerelease

- [ ] There is no nightly artifact concept: every release artifact is tag-triggered, so a tag is the first time those lanes ever run — which is why `release-installers` is 0/5 and `bundle-release` has never run.
- [ ] Build the real artifacts nightly, including GUI bundles and the plugin zips **P1 requested** (`mens-candle-{cuda,metal}-v{version}-{triple}.zip` in `checksums.txt`).
- [ ] **PREREQUISITE — do this before anything else in this task.** The nightly as
      originally written would have published a genuinely public release. Measured:
      `release-binaries.yml:296` uses `softprops/action-gh-release` with **no `draft:`
      and no `prerelease:`**, on `push: tags: v*` — it creates a public, published,
      *latest* release, and `bundle-release.yml` then fires on `release: published`.
      `version-tag-guard.yml` would go red but has no `needs:` edge, so it fails
      *beside* the live release rather than preventing it.
      - Add `draft: true` and `prerelease: true` to that step.
      - Add a PR lint asserting **every** `action-gh-release` step in the repo sets
        `draft: true`. Prove it red by removing the key, capture the output, restore.
- [ ] **The nightly must not push a git tag.** Use `schedule`/`workflow_dispatch` and
      `gh release create --draft --prerelease` on a `nightly-YYYYMMDD` ref that does
      **not** match `v*`, so none of the four tag-triggered workflows fan out.
- [ ] Verify by artifact, not exit code: run it once, then `gh release list` and assert
      every row shows `Draft`, and `gh api repos/:owner/:repo/releases/latest` still
      returns the pre-existing release or 404. Paste both outputs.
