## Global constraints

See the index. Non-negotiable everywhere: assert on the artifact never the exit code (`cmd > /tmp/x.log 2>&1; echo $?`); `cargo test -p X` needs `--all-targets` or it can report "0 passed" when tests live in a bin target; guards must run on macOS (no `grep -oP`); never execute a downloaded binary or set `com.apple.quarantine`.

## Starting premise: separate cancelled from failed

Classifying the last 30 runs of all 47 workflows, and **distinguishing cancelled from failed** — the distinction a first pass missed:

| Class | Count | Remedy |
|---|---|---|
| **ALL CANCELLED** | 8 | Make *faster*. Not broken — slower than the commit cadence, so every run is superseded. |
| **BROKEN** | 13 | Fix or delete. |
| **FLAKY** | 3 | Investigate. |
| **NEVER RUN** | 2 | Delete or wire up. |
| Healthy | ~21 | Leave alone. |

**26 of 47 produce no reliable signal.** ALL CANCELLED: `ci.yml`(28), `compile-matrix`(28), `cr-l-gates`(28), `gui-cross-build`(28), `cr-l8-corpus-feedback`(27), `docs-quality`(27), `mobile-eas-build`, `mobile-e2e-android`.

**Rule — apply it to every judgement in this plan:** never judge a workflow by raw success rate. 0/30-because-always-cancelled and 0/30-because-always-fails need opposite remedies and the raw number cannot tell them apart. Applying it to `cross-platform-check`: 6 success / 1 failure / 22 cancelled = 86% excluding supersessions, i.e. genuinely healthy.

Hosted runners are **free** for public repos (measured: `"billable":{"UBUNTU":{"total_ms":0}}`). Latency, not cost, is the constraint.

## Task 5: Nightly lane and a dated prerelease

- [ ] Publish as a dated prerelease so the release path is exercised daily. **No public release is authorized** — prereleases must stay drafts unless the user says otherwise.
