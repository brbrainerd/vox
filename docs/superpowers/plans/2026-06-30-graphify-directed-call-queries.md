# Graphify Directed Call Queries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose "what calls what" (callers-of / callees-of) over the native code graph by restoring the caller→callee direction the reader discards, plus a constructor-noise filter and (optionally) method-call extraction.

**Architecture:** The live graph's links are stored caller→callee (`{source, target, confidence}`); the reader symmetrizes them (`lib.rs:131-134`), destroying direction. We add directed `forward`/`reverse` indexes alongside the symmetric one, a `Direction` selector on the reader's traversal methods, an optional `direction` param on the two existing MCP tools (default `both` = unchanged), and two discoverable wrappers (`vox_search_callers`/`vox_search_callees`) with a constructor stop-list. Registration goes through the real SSOT (`contracts/operations/catalog.v1.yaml`, regenerated by `operations-sync`), not the generated registry.

**Tech Stack:** Rust, `syn`, `serde_json`, RMCP tool registry (build.rs-generated from a catalog-projected YAML).

**Spec:** `docs/superpowers/specs/2026-06-30-graphify-directed-call-queries-design.md` — READ IT, especially the "What the graph is NOT" honesty section.

**Audit-derived invariants the implementer must respect:**
- Direction is sound (`source=caller, target=callee`, never swapped). Do not "fix" `resolve_edges`.
- The reader is undirected by construction today; `Direction`/callers/callees do not exist yet — these are feature-introduction changes.
- `tool-registry.canonical.yaml` is GENERATED. Hand-edit `catalog.v1.yaml`, then run `operations-sync`.
- Response envelope is `{"success":true,"data":{…}}` — assert `parsed["data"][…]`.
- Adding a field to `GraphifyQueryParams`/`GraphifyPathParams` breaks struct literals at `graph_tools.rs:956, 1089, 919, 993` — each must add `direction: None`.

Replace `lib.rs:166-175`:

```rust
    /// BFS from one or more seed node IDs up to `max_depth` hops.
    ///
    /// `direction` selects callees ([`Direction::Out`]), callers ([`Direction::In`]),
    /// or the legacy undirected neighborhood ([`Direction::Both`]).
    pub fn bfs_from_seeds(
        &self,
        seeds: &[&str],
        max_depth: u8,
        limit: usize,
        direction: Direction,
    ) -> Vec<TraversalHit> {
        let adj = match direction {
            Direction::Out => &self.forward,
            Direction::In => &self.reverse,
            Direction::Both => &self.adjacency,
        };
        bfs::bfs_from_seeds(&self.nodes, adj, seeds, max_depth, limit)
    }

    /// Shortest path between two node IDs (BFS). Returns `None` if unreachable.
    pub fn shortest_path(&self, from: &str, to: &str, direction: Direction) -> Option<Vec<String>> {
        let adj = match direction {
            Direction::Out => &self.forward,
            Direction::In => &self.reverse,
            Direction::Both => &self.adjacency,
        };
        bfs::shortest_path(adj, from, to)
    }
```
