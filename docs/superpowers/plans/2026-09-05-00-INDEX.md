## Why this is partitioned by file ownership, not by topic

Parallel agents on one repo fail in exactly one way: two branches edit the same
file and the second to merge eats a conflict it cannot resolve without the
first's context. Topic-based splits ("do plugins", "do CI") look independent and
are not — five of the seven streams below would otherwise all edit
`.github/workflows/`.

So the partition is **by exclusive path ownership**. Every path in the repo that
this work touches is owned by exactly one plan. A plan may read anything; it may
write only what it owns.

**The rule:** if your task needs to edit a path you do not own, stop and record
it in your plan's *Cross-plan requests* section. Do not edit it.

## Merge protocol

1. **Rebase before merge, never merge upstream into your branch.** Keeps each
   plan a linear, reviewable diff.
2. **Merge order is free** except P2 before P4's final task.
3. On `Cargo.lock` conflict: `git checkout --theirs Cargo.lock && cargo check --workspace`.
4. **Every plan must leave `main` green on its own.** Do not rely on another
   plan having landed.

## Global constraints

Copied verbatim from the spec; every plan's requirements implicitly include
these.

- **Rust toolchain:** pinned via `contracts/toolchain/workspace-toolchain.v1.yaml`.
  Currently `1.96.0`; P2 moves it off a `.0`. Never hand-write a Rust version.
- **No `.0` toolchain pins.** `x.y.0` is the first cut of a release train.
- **No public release is authorized.** Everything must be verifiable without
  publishing to any channel.
- **Assert on the artifact, never the exit code.** `cmd | tail` masks failures;
  use `cmd > /tmp/x.log 2>&1; echo $?`. Every defect this project has hidden was
  something reporting success without verification.
- **`cargo test -p X` can report "0 passed"** when tests live in a bin target.
  Use `--bins` / `--all-targets`.
- **No runtime `cargo` invocation** in any user-facing code path, and no
  remediation string referencing a repo-relative path. An installed user has
  neither a toolchain nor a checkout.
- **Guards must run on macOS.** No `grep -oP` or other GNU-only flags.
- **Never execute a downloaded binary** during verification, and never set
  `com.apple.quarantine`. Both have caused user-visible incidents.
