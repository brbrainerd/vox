## 1. Why ownership is by file, not by topic

Parallel agents on one repo fail in one way: two branches edit the same file and
the second to merge eats a conflict it cannot resolve without the first's context.
Topic splits look independent and are not — five streams would otherwise all edit
`.github/workflows/`.

So: **every path this work touches is owned by exactly one plan.** Read anything;
write only what you own. If a task needs a path you do not own, follow §5.

### Serialized shared files — never hand-edit

These are machine-generated or multi-writer. Conflicts resolve by **regeneration
or union**, never by picking a side.

| Path | Rule |
|---|---|
| `crates/workspace-hack/Cargo.toml`, `.config/hakari.toml` | Any dependency change makes `cargo hakari generate --diff` (a required lint) red. Regenerate and commit **in the same commit**. On conflict: discard both sides, re-run `cargo hakari generate`. |
| `contracts/ci/*.json` (crate-graph, crate-edges.allow, crate-layers, crate-build-map, fan-in-snapshot) | Functions of the dep graph. On conflict: take theirs, re-run the regenerator. |
| `crates/vox-config/src/config_registry.rs`, `contracts/config/config-registry-baseline.txt` | Append one sorted row per new `VOX_*` key. Union-resolve. |
| root `Cargo.toml` | Section-scoped. P2 → `[workspace.package]` + `rust-version`. Anyone → **one `[workspace.dependencies]` row at a time, alphabetical**. `exclude` / `default-members` need an explicit hand-off. |

### Merge order

Free, **except**:

1. **P2's toolchain bump lands last**, or in a merge train with the two version
   rows it needs (§5). Every branch that rebases past P2 pays a full cold rebuild
   of a 96-crate workspace plus a `rustup toolchain install` per worktree — so
   merging P2 late is strictly cheaper, and merging it early with those rows
   missing turns `main` red.
2. **P4 Task 1 after P2 Task 3** — intra-tab in Tab B.
3. **P1's GPU `default-source` flip after P4 publishes the asset.** Landing it
   early converts one 404 into two and removes the gate that made the Metal case
   legible.

## 5. When a task needs a file you do not own

Stop. Do not edit it. Do not "just add one line". In order:

1. Check §2 — the answer may already be settled.
2. Append a row to **Cross-plan requests** in your own plan file, and the mirrored
   row to **Cross-plan inbox** in the owning plan's file. *That inbox row is the
   only edit you may ever make to another plan's file.*
3. Mark the task `- [~] BLOCKED ON P<N>: <one line>` and move on. **Do not stub the
   change locally to unblock yourself** — a stub that later conflicts with the
   owner's real implementation is worse than the block.

An inbox row must be executable with no conversation:

> `| P1 | Publish mens-candle-{cuda,metal}-v{version}-{triple}.zip as release assets and add them to checksums.txt. Consumed by: P1 Task 2. |`

## 6. Concurrency on one machine — read before opening a second tab

Measured: **18 cores**, colima holds **12**, `target/` is **139 GB**, **557 GiB
free**. `.cargo/config.toml` sets `[build] jobs = 24` — already oversubscribed for
one developer.

### Disk is the binding constraint

`target/` is **per-worktree by design**. 7 worktrees ≈ **973 GB** against 557 GiB
free: the machine fills around the fourth agent, and `ENOSPC` does not fail
cleanly — it leaves partially-written rlibs and a corrupt fingerprint database,
producing link errors that look like source bugs.

**70% of `target/` is `incremental/`** (97 GB of 139 GB, 4,571 dirs). Incremental
compilation only helps repeated local edit-compile cycles; it contributes nothing
to a test, check, or CI run. Hence:

```sh
export CARGO_TARGET_DIR="$HOME/.cargo-targets/<tab>"   # never share between tabs
export CARGO_INCREMENTAL=0                             # not optional
export CARGO_BUILD_JOBS=3                              # overrides jobs = 24
```

`CARGO_BUILD_JOBS` = `floor((ncpu - colima_cpus) / n_tabs)`. With colima up and
2 build slots that is 3. **Check `df -h /` before opening each tab; abort below
150 GiB free.**

### Never run two cargo builds at once

`crates/vox-cargo-shim` is a machine-wide build broker with an N-slot
cross-process semaphore. **It has never run** — `~/.vox/build-broker` does not
exist and `which -a cargo` returns only the rustup proxy. Tab 0 installs it.

After Tab 0: `which -a cargo | head -1` must print the shim, then
`export VOX_BROKER_MAX_CONCURRENT=2`.

Before Tab 0, or if the shim is unavailable, wrap **every compiling** cargo call
(`build`, `check`, `test`, `clippy`, `tree --all-features`) — macOS has no
`flock(1)`, so use `mkdir`, which is atomic on APFS:

```sh
#!/bin/sh
# ~/bin/vox-build-slot CMD...
SLOTS=${VOX_BUILD_SLOTS:-2}
DIR=${VOX_BUILD_SLOT_DIR:-$HOME/.vox-build-slots}
mkdir -p "$DIR"
i=0
while :; do
  i=$(( (i + 1) % SLOTS ))
  if mkdir "$DIR/slot.$i" 2>/dev/null; then
    trap 'rmdir "$DIR/slot.'"$i"'" 2>/dev/null' EXIT INT TERM
    "$@"; exit $?
  fi
  sleep 3
done
```

Stale slot after a killed tab: `rmdir ~/.vox-build-slots/slot.*`.

Rules under either mechanism:

- `cargo check --workspace` and `cargo test --workspace` run **once per tab, at
  the pre-PR gate** — never per task. Per task use `-p <crate> --all-targets`.
- Warm the registry **once, serially**, before any tab: `cargo fetch --locked`.
  `~/.cargo/.package-cache` is a single global mutex across every cargo process.
  If you see *"Blocking waiting for file lock on package cache"*, **wait** — do
  not kill it, do not delete the lock.
- A shared target dir would serialize on cargo's directory lock. If you choose
  that trade for disk reasons, expect *"Blocking waiting for file lock on build
  directory"* for many minutes. That is correct behaviour, not a hang.
- Doc-only, YAML-only, TOML-only edits need no slot.
- **No tab modifies a shell profile, `PATH`, `~/.cargo/bin`, or anything under
  `$HOME` outside its worktree while another tab is running.**

## 7. Definition of done

A tab is done when **all** hold:

1. Every `- [ ]` is `- [x]`, or `- [~] BLOCKED ON P<N>` with a filed inbox row.
2. Every Verification bullet ran and its **artifact** is pasted into the PR body —
   real pass/fail counts, real `git diff --stat`, real command output. **Exit codes
   are not evidence.**
3. `main` is green with **only your branch applied**. If your branch needs another
   plan's change to be green, it is not done — split it.
4. No new `Command::new("cargo")` in a user-facing path; no remediation string
   naming a repo-relative path; no `grep -oP`.
5. `cargo hakari generate` re-run and committed if you changed any dependency.
6. `VOX_FMT_CHECK=1 vox run scripts/fmt.vox` clean immediately before the final
   commit — concurrent worktrees routinely land each other's rustfmt drift.

## 8. Global constraints

Every plan's requirements implicitly include these.

- **Rust toolchain** comes from `contracts/toolchain/workspace-toolchain.v1.yaml`.
  Never hand-write a version. **No `.0` pins** — `x.y.0` is the first cut of a
  train, and `1.96.1` existing is the proof for the current pin.
- **No public release on any channel.** Nightlies are drafts, on refs that do not
  match `v*`. `release-binaries.yml` currently sets neither `draft:` nor
  `prerelease:` — fixing that is a prerequisite of P4 Task 5, not a follow-up.
- **Assert on the artifact, never the exit code.** `cmd > /tmp/x.log 2>&1; echo $?`
  — never pipe to `tail`, which masks the exit code. Then:
  `grep -E '^test result:' /tmp/x.log || { echo "NO TESTS RAN"; exit 1; }` — a
  crate whose tests live in a bin target prints `running 0 tests` and exits 0.
- **Standalone builds are the real gate for feature changes.** `cargo check
  --workspace` unifies features and hides under-declared ones; this repo has
  shipped that bug at least twice. For every crate you touch, run `-p <crate>
  --all-targets` *and* the workspace build, and diff the results.
- **No runtime `cargo`** in any user-facing path, and no remediation string
  referencing a repo-relative path. An installed user has neither a toolchain nor
  a checkout.
- **Guards must run on macOS.** No `grep -oP`.
- **Never execute a downloaded binary** during verification, and never set
  `com.apple.quarantine`. Both have caused user-visible incidents in this project.
- **Never delete a user's data.** Uninstall and relocation work on explicit
  allowlists. `~/.vox/.vox-master-key` is 32 unrecoverable bytes; `~/.zshrc` may
  have been created by voxup and since adopted by the user.
