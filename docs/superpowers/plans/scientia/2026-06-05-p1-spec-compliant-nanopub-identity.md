# P1 — Spec-Compliant Per-User Nanopublication Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Emit a spec-compliant, RSA-signed, Trusty-URI-identified nanopublication for one verified claim, signed by a **per-user** identity, validated **offline** against the reference validator — with **no network publishing**.

**Architecture:** Keep `vox-scientia` pure (build + sign + validate given claim data + an RSA profile), put DB/secrets I/O in the `vox-cli` handler (the established `scientia_phase_handlers.rs` pattern). Per-user RSA keys are generated by the `nanopub` crate, stored encrypted in Clavis, and bound to a new `user_identities` row carrying the user's ORCID. RSA + Trusty-URI + offline validation all come from the maintained Rust `nanopub` crate (v0.2.0) — we do **not** re-roll crypto or RDF normalization.

**Tech Stack:** Rust; `nanopub` crate (RSA signing, Trusty URI, offline check); `vox-db` (libSQL/Turso, no CHECK constraints); `vox-secrets` (Clavis vault); existing `vox-scientia::claim_extractor` types.

**Design source:** [scientia-micropublication-ssot-and-surfacing-design-2026.md](../../../src/architecture/scientia-micropublication-ssot-and-surfacing-design-2026.md) §4, §4.1.

## Context the engineer needs (verified facts)

- **DDL pattern:** tables are `CREATE TABLE IF NOT EXISTS` blocks inside the raw-string const `SCHEMA_SCIENTIA` in `crates/vox-db/src/schema/domains/scientia.rs`. Adding a table = add a block there + bump `BASELINE_VERSION` in `crates/vox-db/src/schema/manifest.rs:11` (currently `70`). **Turso has no CHECK constraints** — validate enums in Rust.
- **Precedent rows already in `scientia.rs`:** `scientia_prereg(prereg_id TEXT /* Trusty URI */, signing_key TEXT, …)` and `scientia_discoveries(… human_gate_status TEXT 'pending|approved|rejected', human_gate_reason TEXT …)`. Mirror these.
- **Secrets read:** `vox_secrets::resolve_secret(SecretId::X).expose() -> Option<&str>`.
- **Secrets write EXISTS but is not public:** `VoxCloudBackend::write_secret_v2(secret_id, plaintext, profile, op, source_hint, caller_ctx, history_depth)` in `crates/vox-secrets/src/backend/vox_vault.rs:111`. **Task 3 exports a public `store_secret`.**
- **`vox-crypto` is Ed25519-only** — RSA comes from the `nanopub` crate, not `vox-crypto`.
- **Current user id:** `vox_config::paths::local_user_id()` (`VOX_USER_ID` → OS username → `"local-user"`). No persistent user record exists → `user_identities` is net-new.
- **Existing CLI handler pattern:** `crates/vox-cli/src/commands/scientia_phase_handlers.rs` (handlers do DB I/O, call pure `vox_scientia::*`, print JSON).
