# Docs & homepage maintainability — design

## Context

A design critique of voxlang.org's homepage (session 2026-07-23) turned up a live, verified problem: the deployed site shows the retired `@endpoint(kind: query)` decorator syntax and a non-functional "coming soon" playground, while the repo's `docs/src/index.mdx` has used `@query`/`@mutation`/`@server` and a working `<VoxPlayground>` for weeks. Root cause, confirmed via `gh run view`: `.github/workflows/docs-deploy.yml`'s `deploy-cloudflare` job has failed on **every** push to `main` since at least 2026-07-16 — `CLOUDFLARE_API_TOKEN` (`secrets.CF_API_TOKEN`) is missing the `Account.Cloudflare Pages: Edit` permission (`Authentication error [code: 10000]`). The site has been frozen on a stale build for over a week with no proactive signal anywhere — `docs-deploy.yml` has no failure notification step and nothing else references it via `workflow_run`.

The user asked for a full plan to bring documentation up to date **and keep it that way**, with one explicit constraint: keep `docs/src/index.mdx` synced with `README.md` (an existing intent, marked by `{/* SYNC-FROM-README: name */}` / `{/* SYNC-END: name */}` comments in `index.mdx`) rather than abandon the sync — but stop requiring constant manual upkeep to hold it.

Six parallel research passes against the actual codebase (not assumptions) established the following, each of which reshapes the plan from what a first-glance critique would suggest:

1. **The sync markers are pure comments — nothing has ever enforced them.** Grepped `crates/vox-doc-pipeline/src/**` and `docs/src/contributors/documentation-governance.md` for `SYNC-FROM-README`: zero hits outside `index.mdx` itself. There is no script, no CI check, no include mechanism behind these markers.
2. **Despite that, two of the three marked blocks are currently in sync anyway** (a human has been manually copying them well). `why_vox` and `how_vox` are word-for-word identical between `README.md` and `index.mdx` (only mechanical link-scheme differences: relative vs. absolute GitHub URLs). The `tier_table` block has exactly one real drift: the "Inference (Mens)" row links to `crates/vox-populi/src/inference/mod.rs` in README vs. `crates/vox-inference/` in `index.mdx` — a stale reference from a crate split/rename, not a sync-process failure. A fourth README section, `community_license` (README's own `ANCHOR`/`ANCHOR_END`), has **no** matching `SYNC` block in `index.mdx` at all and has fully diverged in wording. The `## Documentation` intent-table section is unmarked on either side and has also diverged (different rows).
3. **The live-site staleness is NOT a content problem.** Both `README.md` and `index.mdx` already use the current `@query`/`@mutation`/`@server` syntax. The deprecated syntax visitors see is 100% a symptom of the broken deploy (finding 0), not stale source content. This simplifies the plan considerably: no "fix the deprecated syntax in the docs" task is needed.
4. **`README.md` has grown far past its own documented role.** `documentation-governance.md`'s authority map (line 22) already defines README.md's job as "short front door, quick start, tone, links into the book." Reality: 394 lines / 2,640 words, a full hero banner, a pull-quote, five full pillar sections with code blocks, a 20-row stability table, and a references section — reading as marketing copy, not a front door. The homepage (`index.mdx`) mirrors nearly all of it via the sync blocks, so the "flood of information" problem on voxlang.org and the README bloat are the same root cause, not two separate problems.
5. **Governance policy says `last_updated` must never be hand-authored ("the pipeline derives it from Git history... manual dates are considered legacy," `documentation-governance.md:86`) — but this is true for only 25 of 589 files.** `grep -rl "^last_updated:" docs/src` returns **564 of 589** markdown files with a hand-authored `last_updated:` key. `crates/vox-doc-pipeline/src/pipeline/lint.rs`'s `lint_last_updated_vs_git` (lines 380–429) never forbids the key — it only *warns* (not a hard error; not in the `hard_errors` match at `mod.rs:391-410`) when a hand-authored value drifts >30 days from git history, and only on pages with `training_eligible: true`. So the policy is real, current enforcement is a narrow, ignorable warning, and the actual corpus is 96% out of compliance. This is the single largest, most mechanical "make the docs maintain themselves" win available, and it long predates and is unrelated to the homepage critique.
6. **`docs/src/index.mdx` is invisible to the lint tool entirely.** `gather_md_files` (`lint.rs:~165`) only collects files with a `.md` extension. `index.mdx` is the *only* `.mdx` file under `docs/src/` (confirmed via glob), so it currently gets zero frontmatter/category/status/last-updated linting — including on the very `last_updated: "2026-05-05"` value that motivated this investigation.
7. **A real "reality audit" program already exists and is CI-wired** (`vox ci ssot-drift` → `docs_reality_audit::run_verify`, required in `.github/workflows/ci.yml`), but it verifies the *structural integrity* of a 10-item hand-curated claims registry (`contracts/reports/docs-reality-audit/inventory.v1.json`) — that referenced files/globs exist — not prose-vs-code content drift. It is not the right tool to extend for README/homepage sync-checking (no content-diff capability) but is evidence that a narrow, deterministic, CI-gated checker is exactly this codebase's established pattern, which the new sync-checker below follows.
8. **One archival-automation attempt already exists and is dead.** `scripts/quality/archival-enforcer.vox` scans `docs/src/architecture` for `last_updated: 2025`/`2026-01` and force-moves files into `docs/src/archive/` — but it doesn't compile under the current toolchain (flagged CHECK-FAIL in `docs/src/architecture/vox-stdlib-gap-audit-2026-05-23.md:297`), isn't invoked from any CI job or `vox ci` subcommand, and checks the exact hand-authored field governance policy says shouldn't exist. `docs/src/architecture/` is ~301 files, roughly 2/3–3/4 of which read as one-off dated research/audit writeups by filename pattern rather than living reference SSOTs — a real backlog, but not one to auto-prune blindly (false-positive risk: archiving a still-relevant SSOT is actively harmful, and the one existing attempt already demonstrates how a stale automation script silently rots).
9. **`docs-deploy.yml` triggers push-to-`main`-only, with no PR preview and no failure alerting** (`docs-deploy.yml:3-11`, confirmed via direct read). A separate `docs-quality.yml` *does* run on PRs (lint, doctest-md, link check, Starlight build) and is a real pre-merge safety net for content — the gap is specifically the deploy step and its silence on failure, not doc content review generally.

## Approach

Four phases, ordered so each unblocks the next and nothing is proposed before its blast radius is measured against the real corpus.

**Phase 0 — Unblock the pipe.** Restore the Cloudflare deploy (human credential action, outside what an agent should do — documented as a precise handoff) and add a failure-visibility step to `docs-deploy.yml` so the next auth/permission break is never silent for a week again. This is priority zero: every other phase ships docs content that won't reach production until this is fixed.

**Phase 1 — Close the `last_updated` policy-vs-enforcement gap.** A one-time bulk migration (`.vox` script, dry-run first, following `scripts/fix-doc-categories.vox`'s proven pattern) strips the hand-authored `last_updated:` key from all 564 files, then a new hard-error lint rule (`LintKind::HandAuthoredLastUpdated`) makes it impossible for the key to come back — closing the exact gap finding 5 identified, without inventing new machinery (Starlight's `lastUpdated: true` already shows a git-derived date in the rendered page footer; the corpus just needs to stop fighting it). `gather_md_files` is also widened to include `.mdx` (a one-file change today, `index.mdx`) so the homepage stops being invisible to every doc lint.

**Phase 2 — Make the README↔homepage sync self-checking.** Fix the one real content drift (`tier_table`'s Inference/Mens link), decide the fate of the two orphaned sections (`community_license`, `## Documentation`), and add a new deterministic lint pass, `lint_readme_sync`, that hard-fails `docs-quality.yml` (which already runs on every PR) if a `SYNC`-marked block in `index.mdx` no longer matches its `ANCHOR`-marked counterpart in `README.md` after the two known, intentional transforms (relative → absolute link, `docs/src/assets/` → `./assets/`). This is deliberately a **drift detector**, not an auto-syncer: auto-overwriting one side risks silently discarding an intentional edit, and a hard, precise, comparison-based check is both cheaper to build and easier to trust than a fuzzy content-diff.

**Phase 3 — Right-size README and ship the homepage redesign.** Shrink `README.md` down to the "short front door" role `documentation-governance.md` already prescribes for it — this is the actual fix for "I have to constantly edit it," because a 2,640-word marketing README duplicated (in part) into a splash page is inherently high-maintenance, independent of how good the sync tooling gets. The full pitch's canonical home becomes the homepage; README links to it. The homepage itself is rebuilt per the condensed redesign concept already reviewed with the user (progressive disclosure: trimmed hero, a five-item pillar grid instead of five full sections, a five-row status strip linking to a full `/status` page instead of the 20-row table inline, the existing Diátaxis doc-map kept). Fewer, smaller synced blocks is the direct answer to "so I have to constantly edit it" — less content requiring sync, not just better tooling around a large sync surface.

**Phase 4 — Safe, report-only staleness triage for `docs/src/architecture/`.** Replace the dead `archival-enforcer.vox` with a small, git-log-age-based **report-only** lister (no file moves) as the first real tool for finding3 8's backlog — deliberately not automated end-to-end, given the demonstrated cost of a false positive on this corpus.

## Non-goals

- **No AI-based or fuzzy content-diff detector.** The new `lint_readme_sync` check is a precise, deterministic string comparison against known transforms, not a semantic-similarity or LLM judge. If a future SYNC block needs a transform this doesn't handle, extend the transform table — don't reach for fuzzy matching.
- **No automated archival.** Phase 4 stops at "report a candidate list a human reviews," full stop. Auto-moving files out of `docs/src/architecture/` is explicitly out of scope here.
- **No migration off docs-as-code to a wiki platform.** Already assessed in the prior design-critique turn: this repo's existing frontmatter/sidebar/PR-review tooling is the harder-won, higher-quality half of what a wiki gives for free; the missing piece was enforcement (Phases 1–2), not the underlying model.
- **No rewrite of the `docs-reality-audit-program` claims registry.** It's the wrong shape for content-diffing (finding 7); extending it wasn't pursued further.
- **No change to the `docs-quality.yml` PR-gate content checks** (lint, doctest-md, link check) beyond adding the one new `lint_readme_sync` rule — that workflow already does its job.

## Risks / open questions

- **Phase 1's migration touches 564 files in one mechanical pass.** Mitigated by dry-run-first (matching `fix-doc-categories.vox`'s established `DRY_RUN=1` convention) and a `git diff --stat` sanity check before the real run — but this is still the largest single commit in the plan and should land as its own PR, not bundled with anything else.
- **Cloudflare token rotation (Phase 0) requires a human with dashboard access; an agent cannot complete this phase alone.** The plan documents the exact fix and hands it off explicitly rather than treating it as done.
- **Phase 3's README shrink is a judgment call on what counts as "front door."** The task below proposes a concrete target shape (tagline, quick start, one compact pillar summary, license/backing footer, link to the full site) drawn directly from the existing authority-map row, not an arbitrary cut.
