> **Baseline measurements:** `docs/superpowers/specs/2026-05-27-test-suite-baseline-measurements.md`

6. Measured warm wall-clock: `vox-arch-check` script ≤ 30s (from 165s), integration test ≤ 10s (from 117s)

## 2. Baseline Findings (summary)

| Gate / step | Warm wall-clock | Key finding |
|---|---:|---|
| nextest --workspace (no cov) | 170s | 1 test = 117s (69% of total) |
| nextest --workspace (llvm-cov) | 263s | +55% coverage tax |
| vox-arch-check script | 165s | 77% of pre-push fast tier cost |
| vox-arch-check integration test | 117s | Redundant with script work |
| clippy --workspace --all-targets | 75s | Within expected band |
| cargo test --doc --workspace | 51s | Exec is 0.34s; all compile cost |
| vox-cli ci ssot-drift | 15s | Faster than estimated |
| vox-cli ci toestub-scoped | 26s | Faster than estimated |

## 3. Architecture

Two cooperating subsystems plus supporting deliverables.

### 3.1 Subsystem A — `vox-arch-check` internal speedup

**Root cause:** the arch-check pipeline does a full workspace graph walk + batched/per-crate git history scan on every invocation (~100–165s depending on context). It runs twice: once in `vox ci pre-push` (the script path) and once in `cargo nextest run --workspace` (the `arch_check_smoke_test` integration test).

**Changes:**

#### A1. Persistent arch-graph cache

- Location: `target/vox-arch-check-cache/<cache-key>.bincode` (excluded from incremental clean via `.gitignore`)
- Cache key: `sha256(layers.toml + Cargo.lock + where-things-live.md)` — the three inputs that change the graph structure
- On cache hit: load graph, skip workspace walk and git scan, run rule checks only
- On cache miss: full walk, write cache
- Expected hit rate locally: ~90% (most edits don't touch `layers.toml` or `Cargo.lock`)
- Estimated warm-hit time: ≤15s (rule checks without re-walking)

#### A2. Batched git history

- Replace the per-crate `git log` fallback with a single `git log --name-only --format=%H -- crates/` pass, parsed once into a crate→commit map
- Only fall back to per-crate when the workspace has uncommitted changes in a specific crate
- Estimated savings: ~40s on cold (git history scanning scales with crate count)

#### A3. Fixture-based integration tests

- `arch_check_smoke_test` and `description_rule_produces_output_on_clean_workspace` currently invoke the real arch-check binary against the live workspace (~117s each)
- Refactor: extract a `ArchCheckFixture` builder in `crates/vox-arch-check/tests/helpers/fixture.rs` that builds a minimal synthetic workspace (3–5 crates with known layer violations) under `target/arch-check-test-fixtures/`
- Tests exercise rule logic against the fixture, not the real workspace → ≤2s each
- **Keep** one `#[ignore = "slow; runs full workspace arch-check; ci-only"]` end-to-end test per test file for CI parity
- The `--include-slow` / CI flag (see §3.2) controls whether ignored tests run

#### A4. Target time (post-fix)

| Invocation | Before | After |
|---|---:|---:|
| `vox ci run scripts/arch-check.vox` (warm cache hit) | 165s | ≤15s |
| `vox ci run scripts/arch-check.vox` (cold / cache miss) | 165s | ≤40s |
| `arch_check_smoke_test` (default local) | 117s | ≤2s (fixture-based) |
| `arch_check_smoke_test` (CI / `--include-slow`) | 117s | 117s (unchanged; runs real check) |

### 3.2 Subsystem B — Extended `vox ci pre-push`

The existing umbrella already has: fast / complete / full tiers, `--report-json`, `--dry-run`, `--act`, hook installer, heartbeat, `VOX_PREPUSH_BASE` diff-base. Additions only.

#### B1. `--with-coverage` flag

- Allowed only with `--full` (error otherwise)
- Substitutes `cargo nextest run` with `cargo llvm-cov nextest --no-report` during the nextest step
- Adds a `cargo llvm-cov report` step after nextest (emits lcov + HTML under `target/llvm-cov/`)
- Captured in `--report-json` as `coverage_wall_ms`, `coverage_pct`
- Budget: `full+cov` tier budget = measured baseline + 20% headroom = ≤260s (from 263s warm after arch-check fix)

#### B2. `--since <ref>` impacted-crate selector

- Default ref: `origin/main` (matches `VOX_PREPUSH_BASE`)
- Algorithm:
  1. `git diff --name-only <ref>...HEAD` → changed file paths
  2. Map paths to package names via `cargo metadata` package source paths
  3. Resolve transitive reverse deps of changed packages (packages that depend on them) via the metadata dependency graph — avoids false negatives from cross-crate breakage
  4. Run `cargo nextest run --package <pkg1> --package <pkg2> ...` (or `cargo llvm-cov nextest` with `--with-coverage`)
- Applies to `--full` and `--full --with-coverage`
- Falls back to full workspace if `--since` produces more than 20 packages (heuristic; configurable via `VOX_PREPUSH_SINCE_FALLBACK_THRESHOLD`)
- Expected wall-clock for a typical 1–3 crate edit: **3–20s** vs 263s full+cov

#### B3. Slow-test partition

- Mechanism: nextest uses `[test-groups]` and filter expressions. A `slow` group is defined in `.config/nextest.toml`:
  ```toml
  [test-groups.slow]
  max-threads = 1
  ```
  Tests tagged `#[ignore = "slow; ..."]` are excluded from default nextest runs via `--ignore-default-filter`.
- `vox ci pre-push --full` default: runs nextest with `--run-ignored never` (skips slow tests)
- `vox ci pre-push --full --include-slow`: runs nextest with `--run-ignored all`
- CI always runs `--include-slow`
- Immediate candidates: `arch_check_smoke_test` (117s), `timeout_kills_long_running_child` (29s), `generated_ai_fixture_bundle_passes_cargo_check` (25s) — saves ~171s on local full run

#### B4. Budget enforcement

- `contracts/budgets/test-tier-budgets.v1.yaml` — canonical source, format:
  ```yaml
  schema_version: 1
  generated_at: "2026-05-27T00:00:00Z"
  generator: "scripts/perf/test-baseline.vox"
  tiers:
    fast:
      wall_ms_warn: 240000    # 4 min
      wall_ms_fail: 360000    # 6 min
      steps: { ... }
  ```
- `vox ci pre-push` reads budgets file on startup; on `--enforce-budgets` (default locally: warn; CI: fail) compares step durations to thresholds
- Harness regenerates budgets file with `scripts/perf/test-baseline.vox --write-budgets`
- Budget enforcement is a no-op if budgets file is absent (safe on first clone)

### 3.3 Supporting deliverables

#### C1. `scripts/perf/test-baseline.vox`

Reusable measurement harness. Runs each tier serially with `--retries 0` and fixed env, captures:
- Per-tier wall-clock (cold + warm)
- Per-step breakdown (same shape as `--report-json`)
- Top-20 slowest tests (nextest `--message-format json`)
- llvm-cov on/off delta
- Build-vs-run split (nextest `--no-run` then `nextest run`)
- CPU/RAM/disk snapshot at start
- `target/` size

Output:
- `contracts/reports/test-baseline-<date>.json` (conforms to `contracts/reports/test-baseline.v1.schema.json`)
- `docs/superpowers/specs/test-baseline-report-<date>.md` (human-readable)

#### C2. `.cargo/config.toml` knob tuning

- `jobs = 24` (from 8) — uses 75% of logical threads; leaves headroom for llvm-cov instrumentation parallelism
- Uncomment `linker = "lld-link"` (line 13) — requires `rustup component add llvm-tools`; instructions in setup.vox
- Verify `llvm-tools` component is present; if not, emit actionable error and fall back to MSVC linker silently
- Add a comment in `.cargo/config.toml` explaining the rationale (measured improvement range)

#### C3. `target/` pruning policy

- `vox ci dev-loop-audit` (already exists) extended to report `target/` breakdown by subdirectory and age
- New: `vox ci pre-push --prune-stale-target` flag — safe-deletes any `target/` subdirectory last touched >30 days ago that is not `debug/`, `release/`, or `llvm-cov-target/`
- Documents known large dirs: `target/debug/` (instrumented binaries), `target/llvm-cov-target/` (separate for llvm-cov), agent worktree targets (if CARGO_TARGET_DIR fragmentation occurred)

## 4. Gate Tier Matrix

The canonical "what runs when" table. Supersedes §2 table in `docs/src/contributors/local-ci-pre-push.md` (that doc will link here after this lands).

| Tier | Command | Default when | What runs | Target wall-clock (post-fix) | Current wall-clock |
|---|---|---|---|---:|---:|
| **pre-commit** | `vox ci pre-push` (hook: pre-commit steps) | `git commit` | cargo fmt --check, TDD guard | ≤10s | ~5s |
| **fast** | `vox ci pre-push` | `git push` | fmt, line-endings, ssot-drift, scoped TOESTUB, arch-check (cached), scoped doc lint | ≤60s | ~215s |
| **complete** | `vox ci pre-push --complete` | before risky changes | fast + full doc lint/inv + clippy + scoped TOESTUB full | ≤180s | ~325s |
| **full** | `vox ci pre-push --full` | before PR | complete + nextest workspace (slow excluded) | ≤120s | ~495s |
| **full+cov** | `vox ci pre-push --full --with-coverage` | before merge | complete + llvm-cov nextest workspace (slow excluded) | ≤260s | ~590s |
| **full+cov+since** | `vox ci pre-push --full --with-coverage --since main` | tight inner loop | same as full+cov but only impacted crates | ≤20s for 1–3 crate edits | 590s (no selector) |
| **ci-equivalent** | `vox ci pre-push --full --with-coverage --include-slow` | CI parity check | full+cov + slow tests | ≤480s | ~760s |

Note: "target wall-clock" is post-fix (Subsystem A arch-check speedup + B3 slow-test partition). The 260s `full+cov` target assumes arch-check script drops to ≤15s and slow tests excluded.

## 5. Phase Plan

### Phase 0 — Measurement harness (prerequisite, blocks everything)

Ship `scripts/perf/test-baseline.vox` and its schema. Establish baseline numbers in `contracts/reports/`. No feature changes. This phase validates that subsequent gains are measurable.

**Deliverables:** `scripts/perf/test-baseline.vox`, `contracts/reports/test-baseline.v1.schema.json`, `contracts/reports/test-baseline-2026-05-27.json`, initial `contracts/budgets/test-tier-budgets.v1.yaml`

### Phase 1 — Knob tuning (low-risk, immediate wins)

- `.cargo/config.toml`: `jobs = 24`, uncomment `lld-link`, llvm-tools setup instructions
- `target/` pruning: `vox ci dev-loop-audit` extension + `--prune-stale-target`
- Run harness before + after; commit delta to baseline doc

**Expected gain:** 30–60s on cold-compile paths; no impact on warm test execution.

### Phase 2 — `vox-arch-check` speedup (highest-value single change)

In order:
1. A2 (batched git) — low coupling, safe to land first
2. A1 (persistent cache) — depends on A2 for cache key correctness
3. A3 (fixture-based integration tests) — can land independently; requires A1 to prove the cached path is correct

Run harness after each sub-step; gate on ≥50% wall-clock reduction per sub-step.

**Expected gain:** arch-check script 165s → ≤15s warm; integration tests 117s → ≤2s.

### Phase 3 — Slow-test partition (B3)

- Add `[test-groups.slow]` to `.config/nextest.toml`
- Annotate known slow tests: `arch_check_smoke_test`, `timeout_kills_long_running_child`, `generated_ai_fixture_bundle_passes_cargo_check`
- Update `vox ci pre-push --full` to default `--run-ignored never`; add `--include-slow` flag
- Update CI to pass `--run-ignored all`
- Fix the 2 pre-existing test failures before this phase lands (else failures are masked)

**Expected gain (Phase 3 alone, after Phase 2 arch-check fix):** local `--full` 495s → ~325s → ~120s (arch-check 165s→15s + slow excluded 171s); local `full+cov` 590s → ~260s. Phase 4 `--since` cuts this to 3–20s for typical edits.

### Phase 4 — `--with-coverage` + `--since` (B1 + B2)

- B1: `--with-coverage` flag; llvm-cov report step; coverage budget in `contracts/budgets/`
- B2: `--since <ref>` impacted-crate selector; reverse-dep resolution via cargo metadata
- Budget enforcement: `--report-json` budget comparison; `contracts/budgets/test-tier-budgets.v1.yaml` enforcement in CI

**Expected gain:** `full+cov --since main` → 3–20s for typical 1–3 crate edit (from 590s baseline).

### Phase 5 — Budget enforcement in CI

- Add CI step that runs harness after PR merge and compares to budgets file
- Warn if any tier exceeds 1.2x budget; fail if exceeds 1.5x
- Regenerate budgets file on a cadence (weekly or post-major change)
- Update AGENTS.md tier table as canonical reference

## 6. Risks & Mitigations

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Arch-check cache produces false negatives (stale hit) | Low | High (missed violations) | Cache invalidation key includes `layers.toml` + `Cargo.lock` + `where-things-live.md` hashes; CI always runs with `--no-cache` or equivalent |
| Fixture-based tests miss real-workspace behavior | Medium | Medium | Keep one `#[ignore = "slow"]` end-to-end test; CI runs it |
| `--since` misses transitive breakage | Medium | High | Resolve reverse deps in cargo metadata graph; add integration test that verifies a cross-crate breakage is correctly included |
| `lld-link` instability on some Windows configs | Low | Medium | Fallback to MSVC linker if llvm-tools absent; document workaround |
| 2 pre-existing test failures block Phase 3 | High | Medium | Triage and fix / `#[ignore]` before Phase 3 lands |
| `target/` pruning deletes useful incremental | Low | Low | Prune only dirs >30 days old, never `debug/`/`release/`/`llvm-cov-target/`; dry-run mode |
